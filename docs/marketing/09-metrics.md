# Метрики и аналитика SAWAP

Что мерить, как считать, по каким цифрам принимать решения. Привязано к реальной архитектуре
(таблицы `users`, `conversations`, `messages`, `turns`, `turn_events` в `schema.js`).

---

## 1. Северная звезда

**Активный пользователь недели (WAU):** пользователь, сделавший ≥ 3 хода за 7 дней.

Почему не DAU: ассистент — не соцсеть, завысит шум. Почему не установки: не показывают ценность.
3 хода/нед = человек понял пользу и вернулся.

**Модель финансирования:** инвесторы платят за реально активных пользователей — наша
метрическая система = их метрики. Определение «реально активного» фиксируем честно и открыто:
завершённый ход (с синтезом) от уникального верифицированного пользователя Telegram, без
накруток (анти-фрод: темп действий, повторяемость, качество ходов). Никакой искусственной
активности ради цифры — она разрушает и продукт, и доверие инвестора.

## 2. Воронка и метрики по стадиям

| Стадия | Метрики | Цель Q1 |
|---|---|---|
| **Привлечение** | установки бота, переходы по ссылкам, CTR посевов | 3 000 установок |
| **Активация** | /start → открытие Mini App → первый ход | конверсия ≥ 60% |
| **Вовлечение** | ходов на пользователя/день, раскрытие трассы, смена агента, загрузка файла | ≥ 3 хода/польз./нед |
| **Возвращение** | D1/D7/D30 retention | D7 ≥ 25%, D30 ≥ 20% |
| **Виральность** | шеринг ответов, рефералы, вирусный коэффициент | ≥ 0.3 |
| **Широта пользы** | число разных сценариев на активного пользователя | ≥ 3 сценариев |

## 3. Продуктовые метрики качества (уникальные для SAWAP)

Эти метрики отличают нас от «просто чата» и показывают, живёт ли трасса:
- **Доля ходов с раскрытой трассой** — видит ли пользователь «как думает агент».
- **Средняя длина хода (шагов)** и **доля многошаговых ходов** — работает ли авто-глубина.
- **Доля ходов с шагом search/read_url** — реально ли используется агентность.
- **Доля возобновлённых ходов** — работает ли наша фишка «не теряется».
- **Доля ошибок по типам** (vision/search/synthesize) — техническое здоровье.
- **Доля отвеченных без повторного уточнения** — качество первых ответов.
- **Средняя задержка до первого видимого отклика** и **до готового ответа** — ощущение скорости.

## 4. События для трекинга (что писать в таблицу `events`)

Минимальный набор (сейчас аналитики нет вообще — см. аудит P0-4):

```
user_installed        (tg_id, ts)                    — первый /start
app_opened            (tg_id, ts, source)            — открытие Mini App
onboarding_completed  (tg_id, step)                  — прошёл онбординг
turn_started          (turn_id, agent_id, level, has_file, has_image)
turn_completed        (turn_id, status, steps, ms, model)
trace_expanded        (turn_id)                      — раскрыл трассу
agent_changed         (from, to)
message_edited        / fork_used / file_uploaded
share_clicked         (turn_id) / share_completed
referral_sent / referral_joined
fair_limit_shown      (level, used)                  — справедливый лимит (анти-абьюз)
memory_saved / memory_used                           — работа памяти (см. 11-harness-vision)
scenario_completed     (type)                         — закрытый сценарий пользы
digest_opt_in / followup_clicked                      — механики возврата
error_shown           (type)
```

Реализация: таблица `events` + endpoint `track` (по initData, пишет строку). Дешёво, вписывается
в текущую архитектуру без внешних SDK (важно: сторонние трекеры в РФ — лишняя зависимость).

## 5. Дашборд (что смотреть еженедельно)

1. Установки → открытия → первые ходы (конверсия воронки).
2. WAU и тренд.
3. Ходы/пользователь, доля многошаговых ходов, доля раскрытых трасс.
4. Retention-куб (D1/D7/D30 по недельным когортам).
5. Ошибки по типам и топ «упёршихся» сценариев.
6. Шеры/рефералы.
7. Расходы инфраструктуры (стоимость хода / активного пользователя) — контроль CAU.

## 6. План экспериментов (A/B по приоритету)

| # | Гипотеза | Метрика | Ожидание |
|---|---|---|---|
| E1 | Онбординг в 3 экрана увеличит первую активацию | first-turn rate | +15–25% |
| E2 | Кнопка «Поделиться» увеличит приток | share → install | +10% новых |
| E3 | Чипы-подсказки из сервера (персонализированные) увеличат второй ход | second-turn rate | +10% |
| E4 | «Умный заголовок диалога» увеличит возвраты | D7 | +5 п.п. |
| E5 | Follow-up по незакрытым задачам увеличит возвращение | followup_clicked → D7 | +10 п.п. |

Правила: одна гипотеза — одна метрика — один срок (неделя), решение по заранее озвученному порогу.

## 7. Пороговые значения «здоровья» (красные флаги)

- Конверсия открытие → первый ход < 40% → онбординг/крючок не работают, посевы сливать рано.
- D7 < 15% → нет привычки, пересмотреть ценность/уведомления.
- Ошибок > 10% ходов → технический дефект, заморозить рост, чинить.
- Доля раскрытых трасс < 20% → наш главный дифференциатор не доходит до пользователя.
- Стоимость активного пользователя (инфра) выше инвестиционной ставки → оптимизировать
  маршрутизацию моделей (`11-harness-vision.md`).
- Активность без пользы (ходы без завершения, бото-паттерны) → анти-фрод, пересмотреть
  определение активного.

## 8. Связь метрик с решениями (чтобы не мерить зря)

- Низкая активация → чинить первый экран (онбординг, чипы, крючок).
- Низкое возвращение → работать с удержанием (заголовки, «продолжить», уведомления).
- Низкая виральность → усиливать шеринг/рефералку.
- Низкая широта пользы (< 2 сценариев на активного) → расширять каталог сценариев
  харнесса (`11-harness-vision.md`).
