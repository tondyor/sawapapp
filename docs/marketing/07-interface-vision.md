# Концепция «живого интерфейса» SAWAP

Задача от продукта: интерфейс должен быть очень живым, постоянно двигаться и откликаться
на любое уникальное взаимодействие и комбинацию взаимодействий. Этот документ — как это
сделать в рамках текущего стека (React + CSS, Telegram Mini App, без тяжёлых библиотек).

---

## 1. Философия

Продукт — про «как думает ИИ». Значит интерфейс должен **выглядеть как процесс мышления**, а
не как статичный чат. Пользователь должен чувствовать: агент живёт, реагирует, учится на
его действиях.

Три принципа:
1. **Ничего не происходит молча.** Каждое действие — мгновенный отклик (визуал + haptic).
2. **Состояние агента — видно всегда.** Он думает / слушает / отвечает / устал — это эмоции.
3. **Интерфейс помнит контекст.** Повторное взаимодействие не identical — оно богаче.

## 2. Библиотека микро-откликов (что анимировать)

| Взаимодействие | Отклик сейчас | Живой отклик (предложение) |
|---|---|---|
| Тап по кнопке | `scale(0.93)` + haptic | Волна-ripple от точки касания + мягкий glow акцентом агента |
| Ввод текста в композер | нет | Фоновая «звезда» в шапке ярче пульсирует; при 1-м символе аватар агента «оживает» |
| Отправка сообщения | haptic | Пузырь вылетает снизу с пружиной, аватар моргает «принял», трасса открывается с задержкой 200 мс |
| Начало хода | typing-dots | Точка-пульс + пошаговое «проявление» строк плана (уже есть ритм — усилить) |
| Шаг трассы завершён | текст | Иконка шага «щёлкает» в готовое состояние, короткий бегущий блик |
| Ответ готов | bubble | Пузырь «раскрывается» как печатная машинка (появление по абзацам), glow-галочка |
| Выбор агента | sheet закрывается | Цветная волна акцента агента проходит по всей шапке и композеру (смена темы на лету) |
| Глубина хода (определяет SAWAP сам) | Индикатор «силы» разбора: дуга растёт, когда ход многошаговый — без терминов и настроек |
| Ошибка | красный пузырь | Мягкое «дуновение» (shimmer) + честная надпись + предложение действия |
| Копирование | тост | Тост «прилипает» к кнопке, исчезает вверх с галочкой |
| Файл загружается | текст | Круговой прогресс на иконке файла + байты «втекают» в композер |
| Ход остановлен | резюме | Строка трассы «сворачивается» в архивную капсулу |

Правило исполнения: **все анимации ≤ 300 мс, ease-out, отключаемы** (см. §6 про производительность).

## 3. Персоналия агента — «живая эмоция»

Аватар агента (`AgentIcon`) — главный носитель жизни. Состояния:

| Состояние | Что видит пользователь |
|---|---|
| Покой | Мягкое дыхание (масштаб 1 → 1.02, 3 с) |
| Внимание (вводишь текст) | Лёгкий наклон к композеру, «глаза»-точки шире |
| Думает (ход идёт) | Пульс акцентного ореола, точки в глифе бегут по кругу |
| Ответ готов | Короткая улыбка-вспышка, ореол успокаивается |
| Ошибка | Лёгкое «дуновение» вниз, ореол гаснет |

Это достигается CSS-переменными и классами состояния, без картинок: глиф уже векторный,
достаточно анимировать `transform` и `opacity` встроенного ореола.

## 4. Живой фон

Сейчас: статичное SVG-небо с мерцанием. Предложение: фон **реагирует на активность**.
- В покое: редкое мерцание (как сейчас).
- При наборе текста: «звёзды» рядом с композером слегка притягиваются к нему.
- При ходе агента: тонкий поток частиц течёт от аватара в сторону поля трассы (метафора «мысли текут»).
- При готовом ответе: вспышка и возврат в покой.

Реализация: один `requestAnimationFrame`-цикл на фоне с ограниченным числом частиц (≤ 40),
пауза при скрытии вкладки, отключаемо в настройках.

## 5. Трасса как «главный живой объект»

Трасса — уже живая (пульс, бегущий хвост). Усиления:
- **Появление шагов по одному** с лёгким slide-in и бликом — пользователь видит, как строится план.
- **Счётчик времени в реальном времени** с плавным «тикаем» (сейчас обновляется редко).
- **Источники поиска «прилетают»** карточками по мере чтения (каждая ссылка — маленькая карточка с фавиконом).
- **Завершение** — капсула «✓ ответ готов · 4.2 с · 3 источника», которую можно раскрыть.
- **Никаких названий моделей:** в трассе только шаги, источники и время. SAWAP — одна
  сущность; выбор модели — внутреннее дело харнесса.

Это витрина продукта: в ней живёт главный аргумент «показываю, как думает».

## 6. Производительность и ограничения Mini App (обязательные рамки)

Telegram WebView — не десктопный браузер на слабом Android. Правила:
- Только `transform` и `opacity` (GPU-слои); никаких анимаций `width/height/top/left`.
- Общее число анимированных элементов на экране ≤ 5.
- Частицы фона — 1 canvas или SVG с `will-change`, пауза при `visibilitychange`.
- `prefers-reduced-motion: reduce` → отключить всё, кроме цветовых индикаторов.
- Настройка «Экономия анимаций» в профиле (по умолчанию включать на слабых устройствах).
- Ни одна анимация не блокирует ввод текста и не задерживает появление ответа.

## 7. Комбинационная живость (когда взаимодействия складываются)

Интерфейс должен реагировать не на изолированные тапы, а на **сочетания**:
- Отправил фото в сложном запросе → трасса сразу раскрывается на полную (пользователь ждёт долгого — дай ему зрелище).
- Переключил агента **во время** хода → акцентная волна проходит, а трасса продолжает идти — показываем, что смена роли не убивает контекст.
- Второй запрос подряд с fork → подсветка «ты продолжаешь с того же места» (маленькая капсула-уведомление).
- Ход прервался и возобновился → фон даёт «вдох» (частицы возвращаются), капсула «Продолжил с того же места».
- 3+ диалога за день → предложение закрепить агента/тему, «Ты сегодня активен — вот сводка».

## 8. Звук

Опционально, по умолчанию выключено (в Telegram звук часто раздражает):
- Тихий «плink» при готовом ответе (≤ 0.3 с, один раз).
- Шёпот-тик при каждом шаге трассы (только если включено).
- Отдельный тумблер в настройках.

## 9. Как это ложится на текущий код (не разрушая MVP)

Этапы, от дешёвого к дорогому:
1. **Классы состояний** на аватаре и кнопках (уже есть `--accent`, haptic) — 1–2 дня.
2. **Ответ по абзацам** (печать по мере прихода content-событий из `getTurnEvents`) — данные уже потоком приходят, нужно рендерить порциями.
3. **Анимация появления шагов трассы** (CSS keyframes на `rt-step`) — данные уже есть.
4. **Живой фон с реактивностью** (canvas-частицы, привязка к состояниям App) — отдельный компонент.
5. **Эмоции аватара** (переиспользовать `AgentIcon` с состоянием).
6. **Звуки** (WebAudio, маленькие файлы).

Ничего из этого не требует изменения серверной части, кроме потокового контента — и то данные уже приходят кусками.

## 10. Метрика «живости» (чтобы не делать анимации зря)

- Конверсия «первый ход → второй» (живость должна её поднять).
- Время от «ответ готов» до «пользователь раскрыл трассу».
- Доля пользователей, раскрывших трассу ≥ 1 раза (наш главный вовлечённый сигнал).
- Процент пользователей с включённой экономией анимаций (если > 30% — пересмотреть тяжёлые эффекты).
