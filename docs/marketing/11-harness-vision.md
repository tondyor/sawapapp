# Харнесс SAWAP: один агент — весь арсенал NVIDIA

Продуктовое видение движка, который превращает «чат с моделью» в универсального помощника.
Это фундамент маркетингового обещания «любая потребность — любая роль» и главного
удерживающего фактора (пользователь остаётся, потому что продукт становится «его»).

---

## 1. Идея

Пользователь не выбирает модель и не разбирается в нейросетях. Он приносит потребность.
Харнесс сам решает:

- какие шаги нужны для ответа;
- какая модель NVIDIA справится с каждым шагом лучше, быстрее и дешевле;
- какой «специалист» (персона) ведёт каждый шаг;
- что запомнить и что забыть;
- как честно сказать, если что-то не получилось.

**Модель — инструмент, не продукт. Продукт — SAWAP.** Отсюда стратегическое отличие:
у конкурентов линейка моделей и тарифов, у нас — один агент с широчайшим кругом ценности.

## 2. Что уже есть (фундамент в коде)

| Компонент | Где | Состояние |
|---|---|---|
| Роли моделей через `settings` (PLANNER/COMPRESS/REASONING/VISION/DEFAULT) | `lib/config.js` | Смена без деплоя |
| Планировщик шагов (JSON + repair + re-plan) | `lib/agent/pipeline.js` | Работает |
| Исполнители: vision / search / read_url / reason / direct_answer / synthesize | `lib/agent/executors.js` | Работают |
| Сжатие находок до 2000 знаков (дешёвой моделью) | executors | Работает |
| Бюджеты шагов (2–9) по сложности, дубликат-детект | pipeline | Работает; привязка к пользовательским уровням будет снята (см. ТЗ) |
| Навыки агентов (`read_skill`) | `lib/skills/` | Работает |
| Практика проб моделей (замеры TTFB, качества, отсев) | `endpoints/admin*Probe` | Налажена |
| FSM хода в БД, живая трасса, возобновление | `schema.js`, `turn_events` | Работает |

Отсев уже доказал ценность проб: `deepseek-v4.1-flash` — холодный старт 35 с+, `lightning-30b`,
`glm-5.3-flash`, `gpt-oss-20b`, `minimax-m3.1-flash` — отбракованы по замерам. Это и есть
культура харнесса: **модель допускается к работе только после пробы**.

## 3. Целевая архитектура харнесса

```
Потребность пользователя
        ↓
[1] Router     — тип шага → модель (реестр + пробы + бюджет)
[2] Persona    — системный промпт шага (роль-специалист)
[3] Context    — сборка: память + навыки + история + находки, в бюджете токенов
[4] Executor   — вызов модели, инструменты (поиск, чтение, vision, код…)
[5] Guardrails — факт-чек, дисклеймеры, изоляция отказов
[6] Memory     — что сохранить (эпизод / факт / артефакт)
        ↓
Трасса → Ответ
```

### 3.1. Model Registry и Router

- Реестр моделей каталога NVIDIA API с полями: классы задач (текст / глубокое рассуждение /
  vision / код / длинный контекст / эмбеддинги / генерация изображений — по факту наличия),
  скорость первого токена, стабильность, стоимость.
- **Гейт допуска:** модель включается в маршрутизацию только после пробы
  (паттерн `adminModelProbe` / `adminVisionProbe` уже есть).
- Router выбирает модель на шаг по приоритету: качество задачи → бюджет задержки → стоимость;
  fallback-цепочка при недоступности модели (ход не падает, а перестраивается — уже умеем).
- Новая модель = запись в `settings`, без деплоя (паттерн уже есть).
- **Пользователь никогда не видит моделей** — ни названий, ни меток, ни «режимов».
  Всё, что он видит, — шаги, источники и результат одной сущности: SAWAP.

### 3.2. Persona layer — роли внутри одного хода

Сегодня: один агент = один системный промпт на весь ход. Цель: **каждый шаг несёт свою персону**.

Пример хода «Проверь мой договор аренды и оцени риски»:

| Шаг | Персона (системный промпт шага) | Класс модели |
|---|---|---|
| 1. Разбор документа | «Юрист-ревьюер» с протоколом разбора договора | рассуждение |
| 2. Проверка норм | «Правовой исследователь» | + search/read_url |
| 3. Оценка рисков в цифрах | «Аналитик» | рассуждение/математика |
| 4. Синтез ответа | голос выбранного агента (Правовед) | рассуждение |

Реализация: в схему плана шага добавляется `persona` (id системного промпта) и опционально
`model_hint`; executors подставляют промпт шага. Выбранный пользователем агент задаёт «голос
по умолчанию» и базовые навыки; персона шага — узкую специализацию.

Эффект: один запрос — команда специалистов. Круг ценности расширяется **без** расширения
списка агентов в интерфейсе.

### 3.3. Контекст и память — почему пользователь остаётся

| Слой | Что хранит | Где | Зачем |
|---|---|---|---|
| L0 рабочая | Находки текущего хода | `turns.findings` | Уже есть |
| L1 эпизодическая | Краткое резюме диалога после хода | Новая таблица `summaries` | «Продолжим с того места» в другой день |
| L2 семантическая | Профиль: роль, цели, предпочтения, важные факты | Новая таблица `memories` | Ответы «в твоём контексте», без пересказа себя |
| L3 артефакты | Созданные для пользователя тексты/разборы | `deliverables` | Переиспользование: «сделай как в прошлый раз» |

Правила:
- Сборка контекста по приоритету: персона → L2 → L1 → навыки → история (окно 20 сообщений) →
  находки; всё сжимается до бюджета (сжиматель bolt уже есть).
- Факт попадает в L2 только если пользователь прямо сказал или подтвердил («Верно?»).
- **Память прозрачна:** экран «Что SAWAP помнит» — просмотр, правка, удаление. Заодно это
  выполняет право на удаление данных (152-ФЗ).
- Устаревший факт перезаписывается новым; данные не уходят третьим лицам сверх провайдера моделей.

### 3.4. Guardrails

- Фактические утверждения — с источниками (шаги search/read_url уже это дают).
- Отказ инструмента = находка, ход живёт (уже есть).
- Чувствительные темы (право / медицина / финансы) — дисклеймер на уровне UI, не только в промпте.
- Модель не выбирается «по вкусу»: только из реестра с пройденной пробой.
- Память — с явным согласием и с управлением; спорный факт не запоминается молча.

### 3.5. Observability и качество

- Метрики по шагам: доля отказов, латентность, стоимость, повторы/уточнения.
- A/B моделей на одном типе шага (проба + ограниченный реальный трафик).
- Трасса остаётся витриной: пользователь видит шаги, модели (человеческие метки) и источники.

## 4. Каталог сценариев универсальной ценности

Цель — «любая потребность». Каждый сценарий = шаблон плана + персона + классы моделей + слои памяти:

| Сценарий | Шаги | Классы моделей | Память |
|---|---|---|---|
| Утренний бриф | search×N → synthesize | быстрые + рассуждение | L2 (интересы) |
| Разбор документа/договора | vision/text → персона-юрист → synthesize | рассуждение + vision | L3 |
| Обучение/объяснение | reason → synthesize (глубину определяет SAWAP) | рассуждение | L2 (уровень знаний) |
| Текст (пост/письмо) | персона-копирайтер → варианты | текстовые | L3, L2 (стиль) |
| Перевод | direct | лёгкие | — |
| Анализ скрина/фото | vision → reason | vision + рассуждение | — |
| Поиск и сравнение | search×2 → read_url → synthesize | рассуждение | L2 |
| Планирование (день/проект) | reason → synthesize | рассуждение | L1, L2 |
| Код/техническая подсказка | reason (код-модель) | код | L2 (стек) |
| Напоминание / follow-up | synthesize + уведомление | лёгкие | L1 |

Правило расширения каталога: сценарий добавляется, когда (а) есть спрос из реальных запросов,
(б) пробы моделей для его шагов пройдены, (в) качество подтверждено на выборке. Так «широкий
круг ценности» растёт без размывания качества.

## 5. Связь харнесса с удержанием

| Слой харнесса | Почему пользователь возвращается |
|---|---|
| Память L2/L3 | «Меня тут помнят» — не надо пересказывать себя |
| Персона-шаги | Качество растёт без смены сервиса |
| Router + fallback | Работает стабильно, когда «другой ИИ лежит» |
| Каталог сценариев | Новая потребность — тот же вход |
| Трасса | Доверие результату |
| Экономика | Продукт не ставит paywall посреди работы |

## 6. Дорожная карта (привязка к текущему коду)

- **Ф1. Реестр + Router:** вынести реестр моделей в `settings`, добавить пробник-гейт,
  роутинг шага по классам задач. База: `config.js`, `executors.js`, admin-probes.
- **Ф2. Персоны на шаг:** поле `persona` в схеме плана `pipeline.js`, подстановка промпта
  в executors. Агенты остаются интерфейсом выбора «голоса».
- **Ф3. Память L1/L2:** таблицы `summaries`, `memories`; генерация резюме хода дешёвой
  моделью; сборка контекста в `chat.js` / pipeline.
- **Ф4. Артефакты L3 + поиск по памяти:** `deliverables`; семантический поиск, если в каталоге
  есть embedding-модель (проверить пробой), иначе lexical.
- **Ф5. Новые типы шагов:** translate, code, digest, напоминания — по мере проб моделей и спроса.

## 7. Экономика харнесса

- Дешёвая модель на дешёвый шаг (план/сжатие — bolt; тяжёлое рассуждение — по сложности задачи).
- Кэш vision (уже есть) → распространить на повторные чтения страниц.
- Бюджеты шагов и токенов по сложности хода (уже есть) — сохранять как внутренние
  guardrails, без пользовательских уровней.
- Цель: доля дешёвых шагов ≥ 70% без падения качества (мерить по повторным уточнениям
  и отказам). Это главный рычаг CAU — при бесплатности для пользователей.

## 8. Честность

- В трассе нет названий моделей: пользователь видит шаги, источники и время. Модели —
  внутренняя кухня; честность обеспечиваем источниками, а не техническими метками.
- Не обещаем генерацию картинок/видео, пока не пройден пробник и не решён вопрос качества.
- Память — с согласия и управлением; «что помню» — открытый экран.
- Если сценарий не по силам — говорим прямо, а не имитируем ответ.
