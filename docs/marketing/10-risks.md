# Риски и ограничения SAWAP

Что может сломать рост, как этого не сделать. Раздел обязателен к прочтению до
активных посевов и масштабирования.

---

## 1. Технологические риски (высокий приоритет)

### R1. Зависимость от NVIDIA API
Весь «ум» продукта — вызовы `integrate.api.nvidia.com` (`lib/nvidia.js`, `config.js`).
Санкционные/гео-ограничения могут сделать API недоступным или нестабильным для
российских запросов → продукт встанет.
**Митигации:**
- Абстракция клиента LLM уже есть (`lib/nvidia.js`) — держать её единственной точкой входа.
- Резервные провайдеры: локальный хостинг моделей (NIM on-prem), альтернативные API (DeepSeek и др.), российские провайдеры.
- Мониторинг доступности (admin-probe уже есть) + алерт до падения продукта.
- Честно коммуникать: «работает на моделях NVIDIA» — это и есть репутационный актив.

### R2. Молодость Telegram Serverless (tgcloud)
Платформа юная: CLI 0.2.0 с известными багами (см. README), нет таймеров/фоновых задач,
обрыва изолята, лимиты блоба. Продукт уже построен под эти ограничения, но новые фичи
могут упираться.
**Митигации:** держать «хореографию» хода в БД (уже сделано), не планировать фоновых джобов,
читать changelog платформы, иметь план миграции на собственный бэкенд при масштабе.

### R3. Стоимость LLM (инфраструктура)
Продукт бесплатен для пользователей — экономику несёт инвестор. Главный показатель —
стоимость активного пользователя (CAU) против инвестиционной ставки. Прямых «тарифных»
рычагов нет, остаются инженерные: маршрутизация шагов на дешёвые модели, кэш (vision,
страницы), бюджеты шагов, лимиты против абьюза.
**Митигации:** бюджеты шагов по сложности (уже есть: 2–9 шагов), роутер моделей в харнессе
([11-harness-vision.md](11-harness-vision.md)), кэширование, мониторинг стоимости хода,
справедливые лимиты с честным объяснением в UI.

## 2. Санкционные и регуляторные риски

### R4. Доступ к LLM для граждан РФ
Юридически: использование публичных API зарубежных компаний из РФ — зона неопределённости,
особенно при росте продукта. Репутационно: пользователи боятся «что если завтра отключат».
**Митигации:** гео-независимая архитектура (резервные провайдеры), прозрачность, юридическая
консультация по модели работы, возможность быстро переключить бэкенд.

### R5. Персональные данные (152-ФЗ)
Диалоги, файлы, tg_id — персональные данные. Требования: согласие, локализация БД в РФ,
право на удаление, уведомление РКН.
**Митигации:** оферта/политика с согласием при старте, экран «удалить мои данные» в UI,
оценить размещение данных (облако Telegram — проверить соответствие), юрист на этапе масштабирования.

### R6. Маркировка ИИ-контента
В РФ действуют требования по маркировке контента, сгенерированного ИИ (уведомление/марка).
Ответы SAWAP — потенциально такой контент.
**Митигации:** обсудить с юристом форму маркировки, рассмотреть опциональную отметку
«Сгенерировано ИИ» на длинных/публичных ответах, не распространять ответы как факт без проверки.

### R7. Ответственность за советы (право, здоровье, финансы)
Правовед/финансовые темы — зона риска «совет = убыток». Дисклеймер в промпте есть, но
продуктового нет.
**Митигации:** юридический дисклеймер на уровне UI (не только в промпте), не позиционировать
как юридическую/медицинскую помощь, ограничить категорию «опасных» тем.

## 3. Репутационные риски

### R8. Галлюцинации и «вранье» агента
Главный враг доверия к ИИ. У SAWAP есть преимущество — трасса с источниками, но ошибка
источника = ошибка ответа.
**Митигации:** всегда источники у фактических утверждений, честный тон при отказе инструмента
(уже есть), сбор жалоб, быстрое признание ошибки, «не уверен → так и скажи» в промптах.

### R9. Обещания выше возможностей
Генерации картинок/видео у нас нет, «умнее ChatGPT по всему» — не факт. Разочарование = отток.
**Митигации:** обещать только то, что есть (доступ, прозрачность, агентность), честно писать
о границах, не сравнивать «лучше всех».

## 4. Рыночные риски

### R10. Дистрибуция отечественных игроков
Яндекс/Сбер могут скопировать «показ мыслей» и агентные роли, имея огромную аудиторию.
**Митигации:** скорость, ниша (фриланс/малый бизнес), глубина агентной механики (у них — чат),
бренд и виральность в Telegram (их слабое место).

### R11. Узкая команда
MVP сделан малой командой/одним разработчиком. Рост требует контента, поддержки, дизайна.
**Митигации:** фокус на P0-функциях, подрядчики на контент, автоматизация поддержки ботом,
приоритизация по метрикам.

### R12. Инвесторская модель «платим за активность»
Риск накруток, кликбейта и спам-уведомлений ради метрики — разрушает доверие и продукт.
**Митигации:** честное определение активного пользователя (завершённый ход с синтезом),
анти-фрод, запрет dark patterns (`03-brand.md`), уведомления только по явному согласию,
качество пользы важнее счётчика; методика метрик открыта для инвестора.

### R13. Универсальность как размывание
«Помогаем всем во всём» может означать «ни в чём не помогаем хорошо».
**Митигации:** каталог сценариев с барьером качества (сценарий включается только после
проб моделей и проверки на реальных запросах — как уже делается в `adminModelProbe`),
приоритет сценариев по данным запросов, честная деградация («не можем — так и говорим»).

## 5. Юридический чек-лист (до масштабирования)

- [ ] Оферта (условия, лимиты, возвраты, ответственность).
- [ ] Политика конфиденциальности (152-ФЗ: что собираем, где храним, как удаляем).
- [ ] Согласие на обработку ПД при первом использовании (чекбокс/кнопка).
- [ ] Экран «Удалить мои данные» в продукте.
- [ ] Дисклеймеры: не юр./фин./мед. консультация.
- [ ] Оценка маркировки ИИ-контента.
- [ ] Проверка размещения данных (облако Telegram vs требование локализации).
- [ ] В политике отражена передача данных провайдеру моделей (NVIDIA API) и память агента (что храним, как удалить).
- [ ] Пользовательское соглашение для бота.

## 6. План действий при инцидентах

| Инцидент | Действие |
|---|---|
| NVIDIA API недоступен | переключить резервный провайдер (конфиг уже в settings), сообщить пользователям честно |
| Утечка ключа/токена | ротировать сразу (README), проверить логи, сообщить при необходимости |
| Сбой платформы Telegram | статус-страница в канале, объяснить, что ходы сохранены |
| Всплеск жалоб на ответ | разбор, фикс промпта/фильтра, публичное признание |
| Претензия по совету | не обсуждать публично, юрист, усилить дисклеймеры |
