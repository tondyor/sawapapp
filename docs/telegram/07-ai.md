# 07. AI в Telegram: всё, что платформа умеет и позволяет

Telegram — единственная крупная платформа, где все AI-модели могут свободно «встречаться, общаться и конкурировать» (официальный тезис Telegram). Этот документ описывает **обе стороны**: (А) AI, встроенный в сам Telegram, и (B) платформа, на которой вы строите своих AI-ботов/Mini Apps, плюс правила и ограничения.

> Официальная позиция: «*This page and the full Bot API documentation are AI-friendly! If you'd like to build a bot but have limited coding experience, simply direct your favorite AI tool to read our documentation and help you get started.*» — [features.md, AI Agents](https://core.telegram.org/bots/features.md#ai-agents)

## Часть 1 — Встроенный AI Telegram (Cocoon Network)

Telegram развивает **Cocoon** — сеть конфиденциальных вычислений (confidential compute), где запросы обрабатываются «в конфиденциальной среде с нулевым доступом к данным пользователя» (формулировка блога). Все встроенные AI-функции работают через Cocoon; сторонним ботам/Mini App **прямой доступ к Cocoon API не документирован** — только через собственные модели/провайдеров.

| Функция | Релиз | Что делает | Детали |

## Часть 2 — AI-платформа: Bot API и Mini Apps

### 1. AI Agents (официальная секция)

[features.md → AI Agents](https://core.telegram.org/bots/features.md#ai-agents) — прямой ответ «как делать агентов»:

- **многоагентные воркфлоу**: координатор + специалисты (обзор/перевод/расписание);
- **research assistant**: стриминг сравнения нескольких источников + структурированный вывод (rich message);
- **group helper**: вызов по тегу для перевода/фактчекинга/генерации;
- **бизнес-секретарь**: входящие бизнес-сообщения → действия в пределах прав `BusinessConnection.rights`;
- **threaded conversations**: темы в приватном чате с ботом;
- **streaming responses**: показ прогресса + кнопка Stop для пользователя;
- **rich messages**: финальный ответ — отчётом/таблицей/чеклистом;
- **guest bots / inline mode**: вызов агента в любой чате где надо;
- **bot-to-bot + managed bots**: делегирование, оркестрация, построение «персональных ИИ» без кода.

### 2. Гостевой режим (Guest Bots)

Bot API 10.0 (08.05.2026); «AI bots can be mentioned in any private or group chat — even when they aren't members» ([блог, 07.05.2026](https://telegram.org/blog/ai-bot-revolution-11-new-features)).

- Включить: BotFather → Bot Settings → **Guest Mode**;
- триггер: `@имя_бота` в сообщении или reply;
- бот получает `guest_message` (поля: `guest_bot_caller_user`, `guest_bot_caller_chat`, `guest_query_id`) — приходит **выделенный** апдейт;
- отвечает один раз: `answerGuestQuery(query_id, result=InputInlineQueryResult|Message)`;
- **не видит** историю и состав чата; не получает дальнейших сообщений. До **3** ботов в одном сообщении;
- кейсы: «fact-check в этом споре», «переведи», «сгенерируй картинку по описанию в чате».

### 3. Гостевые vs Inline (когда что)

| | Inline mode | Guest mode |
|---|---|---|
| Кто инициирует | Пользователь набирает `@bot query` и получает список карточек | Любой участник тегает бота |
| Ответ идёт | Как сообщение от пользователя («via @bot») | От имени бота |
| Доступ к чату | нет | нет |
| Выбор результатов | пользователем (1 из ≤ 50) | бот выбирает сам |
| Мониторинг | `/setinlinefeedback` + ChosenInlineResult | через обращения/чат |
| Лучше всего для | поиск/шаринг, быстрые утилиты | автономные задачи «сделай Х» |

### 4. Bot-to-Bot Communication Mode

([features.md](https://core.telegram.org/bots/features.md#bot-to-bot-communication))

- включить **Bot-to-Bot Communication Mode** в BotFather (для обоих, если приватные сообщения);
- в группах: `/command@OtherBot` или reply; privacy-disabled/админ-бот видит все сообщения ботов;
- в личке: `sendMessage(chat_id=bot_username)` между ботами;
- через бизнес-аккаунт: бот шлёт ботам своего бизнес-аккаунта;
- **обязательно** защита от петель (иначе платформа ограничит): дедупликация, лимит глубины диалога, rate limiting (например, не чаще одного шага в несколько секунд на пару ботов), глобальный тайм-аут. Telegram предупреждает: «Your bot must remain stable even if another bot intentionally responds instantly and continuously».

### 5. Streaming-ответы (тот самый «печатает как ChatGPT»)

Bot API 9.3 (31.12.2025): `sendMessageDraft` — показать черновик, который дополняется по мере генерации. Bot API 10.3 (24.08.2026): параметры `can_stop` и `keep_on_stop` (пользователь может остановить генерацию; stopped draft оставался видимым).

- Методы: `sendMessageDraft` (текст), `sendRichMessageDraft` (rich-форматированный черновик);
- пустой draft → показывает **«Thinking…»** (или `<tg-thinking>` / `InputRichBlockThinking` для rich);
- финальную версию отправляете `sendMessage` / `sendRichMessage`; draft — временный предпросмотр;
- пользователь может нажать **Stop** → бот получает `message_generation_stopped` / `stopped_message_generation` (`MessageGenerationStopped`) → остановите свою модель/очередь;
- draft ≠ сообщение в истории; чтобы ответ остался — отправьте финальное сообщение после Stop (иначе будет пусто/усечено, если `keep_on_stop=false`).

### 6. Managed Bots (бот создаёт бота)

Bot API 9.6 (03.04.2026) + 10.0 (08.05.2026). Позволяет каждому пользователю «тапнуть и получить своего ИИ-бота»:

- ваш менеджер включает **Bot Management Mode** в BotFather (Mini App);
- пользователь переходит по `https://t.me/newbot/<manager>/<suggested>?name=Name` → создаёт бота без кода;
- вы получаете `managed_bot` апдейт; токен: `getManagedBotToken`; ротация: `replaceManagedBotToken`; доступ: `getManagedBotAccessSettings`/`setManagedBotAccessSettings` (Scopes: `can_use_token`, `can_broadcast`?, см. [ManagedBotUpdated](https://core.telegram.org/bots/api/types/managedbotupdated.md) и [BotAccessSettings](https://core.telegram.org/bots/api/types/botaccesssettings.md));
- у пользователя в чате с менеджером сработает кнопка `KeyboardButtonRequestManagedBot`.

### 7. AI Guardians (join-request фильтры)

Идея из блога 11.06.2026 + API 10.0/10.1:

- бот как admin с правом `can_invite_users` = guard chat;
- заявки → `chat_join_request` + (если нужно проскринить кандидата) `sendChatJoinRequestWebApp` → Mini App с «IQ-тестом/формой» → `answerChatJoinRequestQuery(query_id, …)` approve/decline;
- классический AI-промпт «задавай кандидату вопросы, оцени ответ LLM» в Mini App; для простых групп — свободный ответ через `answerChatJoinRequestQuery` без Mini App;
- Prisma: поле `User.supports_join_request_queries=true` означает, что у пользователя на клиенте есть этот UI.

### 8. Topics в приватном чате с ботом

Bot API 9.4 (09.02.2026) открыла `createForumTopic` в личке. Каждый «проект/кейс/вопрос» = тема. Идеально для ИИ-агента с долгой памятью (в связке с `business_connection_id`/юзерскими тумблерами в BotFather Mini App).

### 9. Ephemeral messages — приватные ответы в группе

Bot API 10.2 (14.07.2026) / 10.3 (24.08.2026): `is_ephemeral` у `BotCommand`, `ephemeral_message_id`, `ephemeral_message_parameters`. Бот может ответить **только этому человеку** в общем чате: «AI ответил вам лично», «результат обработки виден только вам». Ограничения: без callback_query/reply-эфемерного — только администраторы чата могут слать когда угодно; обычные боты — в течение **15 секунд** после подходящего действия пользователя. Полный список типов: текст/медиа/документ/контакт/локация/venue. Редактирование: `editEphemeralMessage*`, удаление: `deleteEphemeralMessage`.

### 10. Rich Messages — идеальный выходной формат AI

Bot API 10.1+ (11.06.2026). Всё, что вы привыкли видеть в ChatGPT-подобных интерфейсах, умеют нативно:

- заголовки, списки, task-lists, цитаты, details-раскрывашки, footnotes, LaTeX (`$…$`, `$$…$$`);
- таблицы (bordered/striped/compact, rowspan/colspan, caption), коллажи, слайдшоу, `<tg-map>`;
- встроенные кнопки (url/callback/web_app/login/copy_text/disabled), мышление `<tg-thinking>` при стриминге;
- лимиты: **32 768** символов, **500** блоков, **16** уровней вложенности, **50** медиа, **20** колонок;
- типичный AI-вывод: «Отчёт → таблица сравнения 5 вариантов → кнопка “Открыть в Mini App” → сноски на источники».

### 11. Mini Apps + AI

- персонаж/настройки/история — полноценный экран; использование внешних AI SDK (OpenAI, Anthropic, open-source) из вашего бэкенда;
- **Serverless** даёт `fetch` с стримингом (SSE) — token-by-token из модели прямо в ваш endpoint;
- Mini App + `sendMessageDraft/sendRichMessageDraft` — просмотр «печатаемого» ответа внутри Telegram;
- платежи Stars (подписки) монетизируют «Pro-рассуждалку»;
- Mini App Store даёт органическую аудиторию (нужен Main Mini App + Stars).

### 12. Serverless как AI-хостинг

Скелет проекта по умолчанию несёт `AGENTS.md` и `docs/tgcloud-sdk.md` — специально, чтобы ИИ-агенты могли писать/чинить бота без подсказки. `npm create @tgcloud/bot` → агент (opencode/Claude Code/Cursor) → «сделай бота, который…» — и работает.

## Часть 3 — Готовые рецепты

### 3.1. Базовый бот с LLM (long polling → LLM → edit)

```
getUpdates → для message: insert в очередь → LLM stream → каждые ~0.5–1 c
editMessageText(chat_id, message_id, partial_text) → final send
```

Плюсы: простота. Минусы: «не стримит анимацией», edit-лимит клиента, сложность с rich.

### 3.2. «Печатает как ChatGPT» (правильный путь)

```
1. onUpdateReceived/handler: sendMessageDraft(chat_id, draft_id?, text="") → «Thinking…»
2. LLM stream chunks → sendMessageDraft(text=chunk_accumulated) (или sendRichMessageDraft с <tg-thinking>…)
3. Final: sendRichMessage (таблицы, ссылки, кнопки)
4. Если пользователь нажал Stop → Update.stopped_message_generation → отменить LLM (abort controller)
```

Параметры: `can_stop=true` (по умолчанию), `keep_on_stop=true` (оставить остановленный текст видимым).

### 3.3. Serverless + SSE

```js
// tgcloud/endpoints/ask.js
import { fetch, api } from 'sdk';
const res = await fetch('https://api.llm/v1/chat/completions', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${process.env.LLM_KEY}` },
  body: JSON.stringify({ model, stream: true, messages }),
});
for await (const chunk of res.body) { /* накопить → sendMessageDraft */ }
```

Вход `Authorization` храните через переменные/секреты платформы — не в коде репо.

### 3.4. Mini App как пульт AI

Главный экран Mini App: история диалогов (список тем), выбор модели/персонажа, лимиты подписки, «Открыть тему в чате» (`t.me/bot?start=topic_<id>`). Кнопка «Перейти в чат» ведёт в соответствующий топик.

### 3.5. Multi-agent система

Coordinator → 2–3 specialist бота: обзор кода, перевод, планировщик. Связь: bot-to-bot mode в группе (reply/упоминания), инициатор = пользователь. Лимиты: 3 гостевых/сообщение, тайм-ауты, дедупликация по content-hash.

### 3.6. Бизнес-секретарь с ИИ


```
1. business_connection → сохраняем rights
2. business_message (входящее) → если can_read_messages: ИИ анализирует → черновик
3. can_reply=true && подходит → sendMessage(..., business_connection_id, text=черновик)
   иначе → уведомление «Вам ответ клиента: хочешь ИИ-ответ?» в пульт в Mini App
```

### 3.7. AI Guardian

`chat_join_request` → `sendChatJoinRequestWebApp(…)` → Mini App «вопрос на вход» → ответ → LLM оценка → `answerChatJoinRequestQuery(approve/decline)`. Формулы: «этичность вопроса ≥ порога → approve». Для антиспама — дополнительно капча своими руками.

## Часть 4 — Правила, ограничения, риски

1. **TOS §4.3 Data Scraping** — AI-боты не могут скрейпить платформу: [telegram.org/tos/bot-developers#4-3-data-scraping](https://telegram.org/tos/bot-developers#4-3-data-scraping).
2. **TOS §5.4 Telegram Business** — выполнение действий от имени бизнес-аккаунта только с корректными правами и human-oversight: [#5-4-telegram-business](https://telegram.org/tos/bot-developers#5-4-telegram-business).
3. **Digital goods — только Stars**: подписка на AI-функции, кредиты на генерацию — через `XTR`. Физтовары (например, «мерч с принтом ИИ») — через провайдеров.
4. **Ephemeral 15 секунд**: без `callback_query_id`/reply-эфемерного — только админы могут слать в любой момент; обычные боты — строго в 15 с после события.
5. **30 msg/s** на бота (1/с на чат, 20/мин в группу). Стриминг дешевле: draft-апдейты с тем же draft_id схлопываются клиентом; «character-by-character» API вызывать не нужно — группируйте с окном ~0.3–1 с.
6. **Точные лимиты draft** не публикуются — рассчитывайте на «несколько обновлений в секунду максимум»; счёт вызовов sendMessageDraft = вызовы к Bot API (каждый считается в rate limit).
7. **Атрибуция**: пользователи знают, что общаются с ботом (бейдж BOT). Не притворяйтесь человеком.
8. **Данные пользователей для обучения моделей** — нет политики «Telegram сдаёт ваши данные для обучения» ни для встроенного AI (Cocoon), ни для ботов (вы решаете сами) — но вы обязаны раскрывать свою модель и её аппетит к данным пользователям.
9. **Галлюцинации — ваша проблема**: добавьте дисклеймеры, исчточники, «проверьте перед использованием»; для мед/юр — эскалация человеку.
10. **Защита от петель** (bot-to-bot): depth limit, max steps, timeout, dedup hash; иначе платформа может ограничить вашего бота.
11. Latency: у LLM могут быть длинные вызовы — Webhook с HTTP 200 быстро, LLM в очередь; не держите HTTP-обработчик открытым на минуты.
12. **privacy-данные**: `message_thread_id`, `business_connection_id` — не логируйте лишние поля без надобности.

## Часть 5 — Что Telegram НЕ даёт для AI

- **Нет хостинга моделей/GPU** — только Cocoon для встроенных функций; модели — ваши (API-провайдеры/self-host).
- **Нет долгосрочной памяти** — хранение истории: ваша БД (SQLite в Serverless, Postgres где угодно).
- **Нет семантического поиска** — RAG вы строите сами.
- **Нет речи-в-текст** для ботов «из коробки» (Whisper как отдельный сервис/библиотека).
- **Не гарантирует** exactly-once и порядке апдейтов.
- Не верифицирует фактическую корректность AI-ответов (ответственность разработчика — Telegram показывает только канал).
