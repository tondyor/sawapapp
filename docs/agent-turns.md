# Агентские ходы: vision-шаг, уровни рассуждений, realtime-трасса

Документация реализации (2026-10-26). Что сделано, почему именно так, чем доказано.

## Задачи

1. Сообщение с изображением → агент **читает картинку** нейросетью NVIDIA API и отвечает по её содержимому.
2. Уровни рассуждений (Лёгкий/Средний/Высокий/Max) работали только на «Быстро» — починить.
3. Шаги агента (чтение изображения, навыки) и ход размышлений — **в realtime над ответом**,
   раскрываются по нажатию (как в агентских чатах/harness'ах).
4. Всё проверено тестами до выката в прод.

## Замеры и ограничения рантайма (важно понимать)

Проверено прямыми тестами через `npx tgcloud run` на реальном API:

| Факт | Значение | Следствие |
|---|---|---|
| Мостик CLI `run` обрывает изолят на ~30с | замер: сон/fetch >30с → «Invalid response (HTTP 500)» | локальные тесты длинных ходов невозможны, только ≤30с |
| **Изолят не живёт после возврата эндпоинта** | фоновая задача не дописывает результат в БД | фоновые «джобы» в этой платформе не работают вообще |
| В рантайме **нет таймеров** (`typeof setTimeout === 'undefined'`) | замер через пробник | никаких `setTimeout`; espera через циклы fetch; в handlers/message 429-retry больше не ждёт |
| Эндпоинт Mini App — JSON-in/JSON-out | официальная docs: Serverless.call → один ответ | стриминг клиенту невозможен; realtime = поллинг второго эндпоинта |
| `fetch` умеет читать SSE-поток по кускам | docs + работает в `lib/nvidia.js` | стрим токенов есть *внутри* изолята — оттуда события пишутся в БД |

Модели NVIDIA API (замеры первого ответа на этом аккаунте, 2026-10):

| Модель | Ответ | Комментарий |
|---|---|---|
| `nvidia/nemotron-3.5-bolt-e4b` | ~0.2с | дефолт, **не** возвращает `reasoning_content`, флаг thinking игнорирует |
| `nvidia/nemotron-3.5-super-vl-120b-a12b` | 0.8–3с (иногда до 20с под нагрузкой) | thinking on/off через `chat_template_kwargs`, **vision** (image_url), NIM отвечает алиасом `private/nvidia/nemotron-3.5-super-120b-a12b` |
| `deepseek-ai/deepseek-v4.1-flash` | **первый токен 35с+** (6 замеров подряд) | в списке моделей есть, image_url принимает, но холодный старт делает его непригодным дефолтом |

Причина исходной ошибки «любой уровень кроме Быстро падает»: 10-секундный таймаут `callEndpoint`
на клиенте + bolt-e4b, у которого thinking-флаг не работает (thinking-уровни давали пустой
`reasoning_content` и зависание ответа).

## Архитектура решения

### 1. Выбор модели (`tgcloud/lib/nvidia.js`, `lib/config.js`)

- «Быстро» (fast) → `DEFAULT_MODEL` (bolt-e4b), thinking off.
- Лёгкий/Средний/Высокий/Max → `REASONING_MODEL` (super-vl), `chat_template_kwargs.thinking: true`,
  бюджет completion-токенов `REASONING_BUDGET` (4096/8192/16384/28000).
- Флаг thinking отправляется только моделям `nvidia/nemotron-3.5*` (`thinkingToggleSupported`).
- `stream_options.include_usage` — токены в meta приходят и при стриминге.
- Адрес модели в ответе NIM нормализуется (снимается префикс `private/`).
- `DEFAULT_MODEL`/`VISION_MODEL` переопределяются через `settings` (таблица settings,
  ключи в `ALLOWED_SETTING_KEYS`), сидируются `endpoints/adminSetSetting` от админа.

### 2. Vision-шаг агента (`tgcloud/lib/chat.js` → `runVisionStep`)

Картинка **не** скармливается основной модели. Ход агента — конвейер шагов:

```
старт
  → 👁 vision-шаг (для каждого изображения последнего сообщения юзера):
      модель-зритель (settings.VISION_MODEL, по умолчанию super-vl) получает
      image_url (data URL, ≤4 картинок ≤3МБ) и системный промпт VISION_READER_PROMPT,
      возвращает фактическое описание (объекты, цвета, надписи дословно);
      описание: событие 'image' в трассу + meta.steps[type=image_read]
      + сохраняется в messages.attachments[].vision
  → 📖 навык (опционально): tool-loop read_skill как раньше
  → размышления (thinking-уровни) → ответ
```

- Описание из `attachments[].vision` подставляется в контекст **всех** последующих ходов
  (`buildLlmMessages` → `messageTextForModel`), поэтому уточнения без новой картинки работают.
- Повторное чтение того же сообщения не происходит: если `vision` уже есть — шаг берёт кэш
  (в событии `cached: true`).
- SVG не читается (текстовый формат, не нужен ридер); не-картинки идут в контекст заметкой
  `(пользователь приложил файл: …)`.

### 3. Realtime-трасса (`tgcloud/lib/turnEvents.js`, `endpoints/getTurnEvents.js`)

- Таблица `turn_events` (schema.js): `turn_id`, `conversation_id`, `tg_id`, `type`, `payload`.
  Миграция применена до деплоя кода (`npx tgcloud migrate --local --yes`).
- Во время хода сервер пишет события батчами (нет таймеров — батчинг по объёму:
  reasoning ≥350 симв., content ≥900 симв., force-flush на границах раундов):
  `start → image* → skill* → reasoning* → content* → done|error`.
- Клиент (`src/App.jsx`) параллельно с `sendMessage` опрашивает `getTurnEvents` каждые 800мс
  и рисует `ReasoningTrace`. Ответ можно получить двумя путями: основной вызов **или**
  done-событие (fallback до 20с) — если транспорт оборвался, ход не теряется.
- `turnId` генерирует клиент (`t-<base36 time>-<rand>`), валидируется на сервере
  (`^[A-Za-z0-9_-]{6,64}$`), события читаются только владельцем (`tgId` из initData).
- Старые события диалога удаляются перед новым ходом (`cleanupConversationTurns`).
- Закрытая трасса хранится вечно в `messages.meta` (`steps`, `skills`, `reasoningText`,
  `tokens`, `latencyMs`) — после перезагрузки трасса восстанавливается (`src/lib/trace.js`).

### 4. UI (`src/components/ReasoningTrace.jsx`)

Свёрнуто: одна строка — статус («Думаю…» / «Изучаю изображение…» / «Размышляю…» + таймер +
метка модели) и бегущий хвост размышления. По нажатию: таймлайн шагов (старт, 👁 изображение
с описанием, 📖 навык, ✓ готов) и полный текст хода размышлений. Live-статус показывается
всегда, пока ход идёт; после завершения — только если было содержание (fast-ответ без
размышлений трассу не рисует).

### 5. Прочие фиксы, найденные по пути

- `src/lib/tg.js`: таймаут 10с → настраиваемый; для ходов агента таймаут снят (0),
  для остальных 15с.
- `src/lib/format.js`: `escapeHtml` не экранировал `&` и `"` (ломал `&amp;` → бесконечное
  «&amp;amp;» и инъекцию атрибутов).
- `handlers/message.js`: 429-retry использовал несуществующий `setTimeout` (краш изолята
  при rate-limit Telegram) — теперь 429 пропускается до следующего батча.
- `endpoints/regenerate.js`: использовал `gt` без импорта.
- `endpoints/editMessage.js|regenerateMessage.js`: принимают `turnId`.
- Имена модулей tgcloud — только буквы/цифры/`_` (дефис в имени файла = «Invalid module name»).

## Доказательство чтения изображений (серверные тесты, реальный API)

Сгенерированные программно PNG (не из кэша моделей), ход целиком через `endpoints/sendMessage`:

| Картинка | Вопрос | Ответ агента | Vision-шаг (meta.steps) |
|---|---|---|---|
| красный квадрат + синий круг на сером | «Что на картинке?» | «красный квадрат частично накладывается на синий многоугольник на светло-сером фоне» | `image_read shapes.png` 1.07с |
| пиксельная цифра 7 | «Какая цифра? Только цифра» | «7» | `image_read digit.png` 0.75с, desc: «…символ цифры «7» в черном цвете…» |
| 4 зелёных круга в ряд | «Сколько кругов и какого цвета?» | «четыре зелёных … выстроены по горизонтали» | `image_read circles.png` 0.82с |
| продолжение без картинки | «что было красным?» | «красный квадрат» (из сохранённого vision-анализа) | кэш не потребовался |

Дополнительно проверено: события хода (`getTurnEvents`): `start, image, reasoning, content, done`;
изоляция по пользователю (чужой `initData` получает пустой список); tool-loop навыков после
рефакторинга (`skills:[{id:'rf-consult-protocol',…}]` + событие `skill`); editMessage с
light-уровнем; токены в meta при стриминге; e2e UI в браузере (мок Serverless.call):
live-статус, раскрытие трассы, image-шаг, fast-ответ без трассы. Тестовые данные удалены.

## Эксплуатация

- Сменить модель-зритель (например, на DeepSeek, помня про 35с+ первый токен):
  ```
  npx tgcloud run endpoints/adminSetSetting "{ key: 'VISION_MODEL', value: 'deepseek-ai/deepseek-v4.1-flash' }" --ctx "{ initData: { user: { id: 1707415385 } } }"
  ```
- Сменить дефолтную fast-модель: ключ `DEFAULT_MODEL` там же.
- e2e UI без Telegram: `npm run build && node scripts/make-dist-test.cjs && npx vite preview --port 4173 --outDir dist-test`
  (мок `scripts/e2e-mock.js`; настоящий SDK вырезается, т.к. перезаписывает `window.Telegram` позже мока).
- Контрольные PNG для тестов: `scripts/test-image.b64` (фигуры), `test-digit7.b64`, `test-circles4.b64`.
